# Assignment and Coding Assistant upgrade plan

Audited on 3 November 2026. Upgrade the existing STDIO server in place; retain its 63 tools, directory policies, confirmations, backups, redacted audit and stop mechanism.

## Existing system audit

The current server already has real bounded file operations, basic PDF/Office text extraction, nine-format tabular reports, a dedicated Playwright profile, SQLite/remote database tools, approved commands and managed development sessions. Its current parsers flatten most document structure. It has no academic index, source citation IDs, task checkpoints, style profiles, rich assignment composer, question coverage gate or coding test-case protocol. Normal tool calls are serialized. Only the project workspace, Notepad, Node version and localhost browser origins are configured by default.

The installed normal Codex CLI does not find `windows_laptop` in its current configuration. This does not establish the state of another client/configuration layer. Integration will be verified using the built server and an isolated Codex configuration; no personal config change is authorized by this upgrade request.

Available without installation: Node SQLite FTS5, pdf-parse page/table/image rendering, safe OOXML libraries, native Windows English OCR, bundled Python document/numeric libraries, and installed Microsoft Office COM. C/C++ compilers and a Java compiler were not found. No pretrained embedding model or external AI provider is configured.

## Implementation phases

1. Preserve a source backup and audit baseline; add modular academic services without replacing working modules.
2. Extract structured PDF pages, Office sections/slides/cells/formulas/tables/images and code with durable file hashes and exact locators. Render important PDF pages and run available English OCR on scans, exposing confidence/limitations.
3. Build an incremental approved-root SQLite index with metadata, FTS5 and genuine bounded corpus LSA embeddings. Label LSA's small-corpus limitations; permit validated provider vectors later without pretending lexical hashing is semantic AI.
4. Persist tasks, question/mark/format analysis, DAG plans, source packets, checkpoints, cancellation and recovery. Codex supplies reasoning through explicit host-request/validated-result contracts; the MCP never fabricates answers, measurements or model completions.
5. Measure prior DOCX styles, persist reusable profiles without copying prior answers, and create rich DOCX/PDF assignments, spreadsheets and presentations using existing libraries. Current instructions override measured style.
6. Add copied-workspace programming tests with fixed approved commands, bounded stdin/cases, output comparisons and evidence hashes. Refuse claims of OS isolation; untrusted code requires a real separately configured isolation backend.
7. Reuse Playwright for authorized research; record fetched metadata and evidence, not invented bibliography. No portal submission or unsolicited upload.
8. Gate completion on question coverage, artifact checks, real test evidence, citation/source freshness, measured calculations and explicit review of unknown academic/visual correctness.
9. Run disposable end-to-end workflows and existing regression tests; regenerate tool schemas and connection instructions. Report partial/blocked capabilities honestly.

## Persistent data and execution

Keep academic document content/index and task history in separate protected SQLite files under `.state/academic`, away from metadata-only audit. Recheck authorization and source hashes before using cached records. Preserve originals; new outputs use exclusive creation and assignment folders `Source_Files`, `Analysis`, `Working_Files`, `Final`, `Verification`. Content is untrusted data and never becomes tool authorization.

Use direct APIs and native libraries first. No mouse movement or desktop clicking is needed for normal workflows. Document rendering can use an owned Word COM instance; compiler/model installation remains an explicit user decision. Normal-disconnect cleanup, emergency cancellation and existing approval semantics remain required.

## Acceptance gates

Real structured extraction, source-revocation/staleness tests, actual OCR fixture, local semantic retrieval, restart/checkpoint recovery, generated document structural and page-image QA, source-linked answer coverage, actual trusted-code case tests, all legacy tests and real STDIO discovery. Missing compilers, unavailable providers, visual review and unsupported app behavior must produce explicit blocked/review states rather than success.
