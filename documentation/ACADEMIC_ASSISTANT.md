# Assignment and Coding Assistant

This is an in-place upgrade to Windows Laptop Control MCP, not a replacement server or a separate ChatGPT UI robot. The original tools remain available. Codex supplies reasoning and writing; the MCP supplies bounded extraction, discovery, persistence, native generation and verifiable execution. Calling a plan/checkpoint tool never silently generates answers or executes its listed tools.

## Activate and begin

The existing installed dependencies suffice. Run `npm run build`, then restart the MCP connection in your actual client. `npm run check` builds, tests, verifies STDIO discovery and runs a disposable assignment workflow. No new npm packages, models, compilers, Windows services or system configuration changes are required for the implemented upgrade.

The normal `C:\Users\MSI\.codex\config.toml` was inspected only for a matching local server, and no entry was found. Another client/config layer may differ. Use `node scripts/register-codex.mjs` to preview the actual STDIO entry; applying it remains an explicit local approval step. Never replace an unknown working connection merely because its name differs.

Only this project's `workspace` is currently authorized. Add your assignment directory through the existing local `configure --add-root` process, review the change and restart. The upgrade does not grant itself access to Documents, Desktop, other drives, browser sessions or credential files.

After connection, tell Codex: “Use the academic workflow to find and prepare my Lab 04, using my lecture notes and Lab 03's format.” The `assignment_workflow` MCP prompt and `academic_capabilities` provide the operating procedure. Native windows, desktop clicks and visible applications are unnecessary for ordinary document/coding workflows.

## Source-aware assignment workflow

1. Create a persistent task with the actual instruction text and explicit input files. Extract the instructions, identify every question/subquestion, marks, constraints, output formats and missing essential data. The deterministic question parser is only a draft; Codex reviews/corrects it before saving `academic_task_plan` with `requirementsReviewed: true`. Specify `deliverableContracts` for each final format/name/path and its required question IDs; `academic_task_deliverables` can revise these mappings without pretending answers or output checkpoints remain unchanged.
2. Preview and build the authorized index in bounded batches. Continue `nextCursor` until null; a traversal limit is reported explicitly. Use metadata/full-text discovery first, and fit local LSA for corpus semantic/hybrid search. Refit after corpus changes. Search results include file hash, source ID, segment ID and real page/slide/paragraph/sheet/cell locators.
3. Read relevant lectures and previous work with structured extraction. Use actual page/image views for important diagrams. Scanned PDFs are flagged; `academic_pdf_ocr` renders a specified page into a new working PNG, uses installed Windows OCR and persists a source/page/language/raster-hash-bound record. Canonical extraction/indexing/reasoning then share the same actual OCR segment IDs. Reindex after new OCR. Replacing OCR provenance changes canonical source IDs even if the PDF bytes are identical; use `academic_task_resume` with `refreshSources: true`, re-review the plan and prepare new grounded answers when this invalidates a task. English en-US/en-GB are available here. Unsupported languages remain blocked; nothing is downloaded automatically. OCR and vision interpretations require review. Metadata search can find an unreadable file by name but returns no invented citation segment.
4. Measure a prior DOCX with `academic_style_analyse`; optionally save it with a nonpersonal label. Fonts, size, spacing, margins, headings and paragraph metrics are evidence, not a claim about writing quality or lecturer intent. Codex examines the content for explanation depth, reference conventions and subject-specific style, then can save reusable `academic_style_guidance_set` notes with matching current segment quotes. Retrieve them with `academic_style_guidance_get`. Whitespace-only or invented excerpts are refused, and changed/revoked templates cannot authorize cached guidance. These are source-supported host interpretations. Save authoritative current-task requirements in the plan; they override saved guidance and measured formatting. Do not copy another student's answers or reuse unverified submissions.
5. Claim a ready step. `academic_reasoning_prepare` returns a structured source packet and response schema. Codex reasons using the command word, actual marks and evidence, then calls `academic_reasoning_commit`. The server validates question coverage, source hashes, citation IDs, excerpt quotes and observation names. It does not pretend to call an unconfigured AI model. Missing facts/references remain uncertain.
6. Keep theoretical explanations, calculated values and supplied observations distinct. `academic_task_observations` requires source hashes and values actually present in the supplied source. This verifies provenance, not whether a student really performed the experiment. Missing laboratory measurements block completion; calculations never become fabricated observations.
7. Generate new deliverables in the assignment's `Final` directory. Sources/templates are never overwritten. Checkpoint the output paths and hashes. A later changed source/output or OCR interpretation invalidates affected work and reviews.
8. Inspect the actual output, run computed QA and test cases, record explicit source-aware technical/layout reviews, then verify and finalize only when no blockers remain. Verification parses the actual final file formats and requires the complete committed explanation in each mapped prose artifact after conservative Unicode/whitespace normalization. Code artifacts instead require exact tested-byte evidence. A host's positive notes cannot make a renamed/malformed DOCX, unrelated text file or missing answer pass. Export JSON/Markdown QC with `academic_task_quality_report`. Finalization never submits or uploads work.

### Deliverable mappings and advisory planning memory

Use contracts such as `{id: "report_word", format: "docx", name: "report.docx", questionIds: ["q1", "q2"]}` and the corresponding PDF contract when both versions must contain the answers. Supporting spreadsheets/slides can explicitly use `questionIds: []` when the main reports contain all answers. Every question must map to at least one real final artifact. Exact legacy filenames/formats are conservatively inferred; vague strings such as “a polished report” require reviewed explicit contracts. Structural validity and answer presence are checked again at finalization. If the prose wording changes during editing, recommit that reviewed final wording rather than bypassing the content check.

`academic_task_brief_set/get` stores advisory topic, required-software/constraint notes and a host-reviewed effort interval with assumptions and unknowns. It does not amend authoritative requirements or prove measured runtime. **Promote any new constraint through `academic_task_plan` before execution**; this invalidates affected work/reviews through the existing requirement checks. Briefs become stale when semantic task scope, supplied observations, canonical sources or output contracts change. Observation-only sources are reauthorized too. Use nonpersonal subject labels and keep secrets out of memory.

Historical completed statuses are preserved, but a QC report based on old verification that lacks the v1.2 integrity checks is marked stale/needs-review. Explicitly resume and verify such a task under the new rules rather than silently grandfathering the old pass.

## Documents and styles

`academic_document_compose` creates rich DOCX headings, paragraphs, tables, images with alt text/captions, code blocks, native equations/fractions, references, margins, page fields, headers/footers and optional TOC. A prior style profile supplies measured defaults; only explicit current overrides replace them. Tables must have matching column counts. Use concise content and review rendered pagination.

`academic_document_patch` makes a new copy and replaces an exact, unique text occurrence within one DOCX text run. Other ZIP parts remain byte-identical. Ambiguous/split-run replacements are refused instead of damaging mixed formatting. Full arbitrary Word editing and pixel-perfect replication of every template are not claimed.

`academic_document_render` exports an authorized clean DOCX to a new PDF via an owned Microsoft Word COM instance, with macros, active external fields and links blocked. It refreshes only TOC/PAGE/NUMPAGES fields in memory, never generic active fields, and never saves changes to the source. It refuses when another Word process is already open, so it cannot attach to personal work. An owned job closes its process on cancellation. Word is not made visible and no cursor input is injected. Keep Word closed during this conversion; unsupported/busy cases return a real error.

`academic_pdf_generate` produces a text-focused PDF directly. For rich DOCX fidelity, use Word export instead. `academic_document_quality` checks structure, required text and blank PDF pages; page-image output uses actual rendered pixels. Machine checks leave visual and technical correctness at `needs_review`. Never skip inspecting every final PDF page. Fields/TOC rendering can vary by Word; verify the actual exported result.

## Calculations, spreadsheets and presentations

`academic_calculate` evaluates a small arithmetic grammar with explicit numerical variables, expected values and tolerances; it never executes supplied code. Units and scientific suitability require review. Standard mathematical power/unary rules apply.

`academic_spreadsheet_generate` writes explicit XLSX cells, supported formulas and independently computed caches. Its formula evaluator uses Excel power/unary precedence and ROUND halfway away from zero; referenced-range booleans are ignored in aggregates. SUM, AVERAGE, MIN, MAX, COUNT, ROUND, SQRT, ABS, selected trigonometry/log/power and bounded arithmetic/ranges are supported. External references, arbitrary functions, cycles and excessive ranges fail. It is not a complete Excel calculation engine; unsupported formulas must use a separately approved trusted tool rather than guessed results.

`academic_presentation_generate` creates PPTX titles, readable bullets, native tables, images, notes and supplied source references. Table and bullet bodies use separate slides to avoid overlap. Visual review remains required. Advanced animation/template replication is outside this generator.

## Programming assignments

Codex reads the full problem, chooses an allowed algorithm/language, writes the source and explains it. The new engine executes only fixed locally approved compile/run command IDs; it does not invent a compiler installation. Explicit source files are copied to a new working directory; tests feed bounded stdin and compare actual stdout/exit status using exact/trim/line rules. Preview produces a hash over sources, commands, cases and restrictions. Applying requires that same current hash and confirmation.

Node/Python mechanics, compilation-stage behavior, failures, stdin, output comparisons, cancellation and hash-bound evidence were tested. Actual production execution refuses elevated tokens and untrusted code. This session's token is elevated, so start Codex/MCP normally as a non-administrator before running trusted assignment code. C/C++ compilers and javac were not found. Their installation and any real VM/container isolation backend require separate approval. The engine supports their configured command protocol, not an already installed toolchain.

A copied workspace is not an OS sandbox. Trusted commands run as your account, with a sanitized child environment and bounded output/time but without enforced filesystem/network isolation. Untrusted code is refused because no real isolation backend is configured. Commands must remain foreground; detached/daemonizing code can escape same-user process-tree cleanup. Assignment library/technique restrictions require a separate current host review even when declared tests pass.

## Research and AI integration

Use official/academic sources and verify their actual pages. API-first `academic_research_fetch` uses only authorized exact origins, bounded GET, checked redirects and no cookies/authentication. It stores actually fetched URL/title/author/date/DOI metadata; absent fields stay null and peer-review status is not inferred. The existing Playwright tools handle authorized dynamic sites. A search-plan tool returns a URL plan, never fabricated search results. Bibliographic metadata claims still require source review.

The provider boundary defaults to explicit Codex-host reasoning requests/results. No separate API key is required, no ChatGPT UI is clicked, and Codex credentials are not extracted. External APIs or pretrained embedding models are not configured. Local LSA is genuine TF-IDF/truncated-SVD corpus embedding, capped at 800 chunks/600 terms/24 dimensions in a cancellable worker. It can recover corpus co-occurrence relationships but is weaker than modern pretrained semantic models, cannot understand unseen vocabulary and cannot establish factual truth. Full-text remains available beyond the LSA training cap.

## Persistence and recovery

Protected `.state/academic` contains separate index, task/reasoning, style and research databases. The audit store remains metadata-only. Academic stores contain authorized source excerpts/index text and answer history and must be treated as private user data; they are not encrypted by this application. Task memory rejects recognizable credential patterns, but automatic redaction cannot identify every sensitive fact. Do not supply secrets or private personal details as task memory.

Checkpoints use task revisions, validated acyclic dependencies, source/output hashes and explicit status. At most two ready independent steps are suggested to Codex; write/browser/native state is still controlled. Cancellation/status bypass the normal queue. Running work becomes interrupted on disconnect/restart; unknown external effects remain awaiting inspection and are never replayed automatically. Completed work is reused only when its dependencies and artifacts remain current.

Use the existing emergency stop for all managed work. No tool clears it. Do not delete academic stores or source backups until you have exported needed work and stopped the server.
